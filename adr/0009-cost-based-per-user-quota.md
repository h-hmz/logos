# Cost-based per-user quota

Each Firebase UID gets a lifetime budget of generation cost in USD (default $1, uniform for all new users), spent across both debate turns and tutor replies. We meter actual provider cost (OpenRouter's post-hoc `RunMetrics.CostUSD`) rather than a count of requests, because a single "generation" can vary widely in cost and a dollar budget bounds real spend the way a request count cannot. The budget is checked and decremented in the service layer (`NextTurn`/`TutorExplain`), with the caller UID passed in explicitly; each user's spend *and their ceiling* live in a `quotas/{uid}` document (`spent_usd`, `spend_limit_usd`) accessed through a `QuotaStore` interface (mirroring the `Repository` pattern of ADR 0001) and recorded with the same optimistic version-checked Firestore write used for debate state (ADR 0004). The configured limit seeds `spend_limit_usd` when an account is first created and is ignored thereafter, so the account's own stored ceiling governs. The feature is gated by `QUOTA_ENABLED`. On each generation the service first acquires an in-memory per-UID lock (refusing with **409 Conflict** if one is already held), then reads spend and refuses with **402 Payment Required** if the user is over budget; otherwise it runs the generation and adds the actual cost. Builds on ADR 0007 (all LLM traffic via OpenRouter for prepaid spend caps), which is also what makes per-generation cost observable.

## Considered options

- **Count-based quota (N generations/period):** simpler, but doesn't bound cost — a cheap and an expensive generation count the same.
- **Windowed/daily reset:** rejected in favor of a lifetime budget; simpler accounting (a single accumulating `spent_usd`, no window key) and a firmer total-cost ceiling for a small allowlisted user base.
- **Reserve an estimated max cost up front, reconcile after:** would prevent overshoot entirely but requires a per-model price table we don't maintain. Rejected for the simpler allow-while-under-budget approach below.

## Consequences

- **Cost is known only after the call.** We allow a generation whenever `spent < limit` and add its actual cost afterward, so a user can exceed their limit by at most one generation's cost — already bounded by the `MaxCompletionTokens` cap (ADR 0007).
- **The limit is snapshotted per account, not read live from config.** Each account stores its own `spend_limit_usd`, seeded from the configured default at creation. Changing `QUOTA_USD_LIMIT` later moves the ceiling only for users who don't yet have an account; existing users keep what they were created with. This makes a user's budget stable and auditable (it can't silently shift under them), and is the seam a future per-user/tiered limit would grow from — set the field at creation, or migrate it, without touching the enforcement path. The trade-off: lowering the global default does **not** claw back already-provisioned users; that would need an explicit migration over the `quotas` collection.
- **One generation in flight per user, per instance.** An in-memory per-UID lock serializes a single user's generations so they can't fan out concurrent calls to dodge the pre-flight check. The lock is process-local, so across N Cloud Run instances a user can still run up to N concurrent generations — bounding worst-case overshoot to N generations' cost rather than 1. Accepted: at sub-cent costs against a dollar budget this is negligible, and a cross-instance lock would mean a distributed lock we don't want.
- **Failed generations are free.** `RunMetrics.CostUSD` is ~0 on error, so nothing is charged for failures.
- **Fail-open.** If the quota store can't be read or written, generations are allowed and the lost deduction is logged. A real Firestore outage already breaks generations (debate state lives there too), and once a generation has run the money is spent — failing the user as well is the worst outcome.
- **Quota gating precedes SSE streaming.** `next` can stream via SSE, which commits a `200 OK` before any generation work. The lock acquisition and budget check therefore run before the SSE writer is created, so over-budget/in-flight rejections return a real 402/409 with no stream opened. Only failures that occur after streaming has begun (e.g. a mid-call LLM error) ride the SSE `error` event, as they do today.
- **Depends on a provider that reports cost.** If `LLM_BASE_URL` points at a provider that doesn't return `usage.cost`, `CostUSD` is 0 and the budget never depletes — quotas silently become a no-op. This is acceptable because ADR 0007 already standardizes on OpenRouter.
